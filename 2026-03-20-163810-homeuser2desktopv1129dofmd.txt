● v11_29dof 简化与楼梯通过训练计划——运控专家评估报告

  ---
  总体判断

  整体可行性：可行，但有两处结构性风险需要在执行前处理。

  问题诊断准确：当前"楼梯前驻停"是多重惩罚合力的保守策略平衡点，而非策略"不会走
  楼梯"。解决方向（降维、解耦、放宽阈值、驱动前向）正确。

  ---
  一、结构性风险（必须处理）

  风险 1：AMP 降维操作的统计一致性问题

  将 amp_policy/amp_reference 的 joint 状态降维为下肢+腰，会破坏 discriminator
  的统计基础：

  - MoCap 参考数据通常是全身录制的，上肢摆动对步态动力学有关联影响（角动量守恒）
  - 截取下肢状态转换 $(s_t^{\text{lower}}, s_{t+1}^{\text{lower}})$
  已不是真实人类步态的正确分布
  - 可能导致 discriminator 快速饱和或训练不稳定

  建议：改用方案 B（上肢 scale 降至 0.1），而非对 AMP 观测空间降维。
  工程成本低、可逆、不破坏 discriminator 统计基础。

  风险 2：volume_points_penetration 下调缺乏量化锚点

  过大地下调会导致策略用躯干碰撞台阶边缘通过，仿真侥幸但真实部署直接失败。必须与
   dont_wait 联动调整（建议 2:1 步调）。

  ---
  二、Sim-to-Real 风险

  楼梯场景为高风险，接触模型是最难精确仿真的来源，而楼梯恰好对接触质量最敏感：

  ┌──────────────┬──────┬──────┬───────────────────────────────────────┐
  │   差距来源   │ 平地 │ 楼梯 │                 说明                  │
  ├──────────────┼──────┼──────┼───────────────────────────────────────┤
  │ 接触模型误差 │ 中   │ 极高 │ 脚踏台阶边缘接触面积/法线极难准确建模 │
  ├──────────────┼──────┼──────┼───────────────────────────────────────┤
  │ 执行器延迟   │ 中   │ 高   │ 脚悬空动态调整对 10-20ms 延迟更敏感   │
  ├──────────────┼──────┼──────┼───────────────────────────────────────┤
  │ 地形几何误差 │ 低   │ 高   │ 台阶高度误差 2-3mm 即影响落脚成功率   │
  └──────────────┴──────┴──────┴───────────────────────────────────────┘

  补充 DR 配置建议（楼梯专项）：
  - 台阶高度随机化：标称值 ±5mm
  - 执行器延迟上限：15-20ms
  - 脚底摩擦下限：0.4（楼梯面通常比地面光滑）
  - PD 增益扰动：±20%，踝关节重点测试

  ---
  三、训练稳定性

  dont_wait 与 volume_points_penetration 梯度方向对立，单边操作会导致策略收敛到"
  用上半身倾斜代替脚步前进"的无意义局部最优。

  课程阶段切换条件应量化（不应依赖时间节点）：
  - Phase 1→2：驻停率 < 30% 且 base_contact 终止率 < 15%
  - Phase 2→3：连续通过步数中位数 > 5 步，且 root_height 终止率 < 10%

  AMP 收敛监控信号：
  - discriminator 损失 < 0.2：过于强大，减小 w_style
  - discriminator 损失 > 0.8：已崩溃，重置 discriminator
  - 楼梯任务建议 w_style 初始值为 0.3（而非通常的 0.5）

  ---
  四、29-DOF 简化策略对比

  ┌──────────────────┬─────────────────────────────┬─────────────────────┐
  │                  │   方案 A（固定默认姿态）    │ 方案 B（scale=0.1） │
  ├──────────────────┼─────────────────────────────┼─────────────────────┤
  │ AMP 兼容性       │ 破坏统计基础                │ 完全兼容            │
  ├──────────────────┼─────────────────────────────┼─────────────────────┤
  │ 角动量守恒       │ 破坏                        │ 基本保持            │
  ├──────────────────┼─────────────────────────────┼─────────────────────┤
  │ 回退成本         │ 高（固定→活动有动力学突变） │ 低（调一个参数）    │
  ├──────────────────┼─────────────────────────────┼─────────────────────┤
  │ Phase 3 回补难度 │ 高                          │ 低                  │
  └──────────────────┴─────────────────────────────┴─────────────────────┘

  明确建议：优先实施方案 B（scale=0.1）

  ---
  五、楼梯感知架构——最重要的缺失

  整份文档聚焦奖励/动作空间调整，但完全没有涉及楼梯感知。

  volume_points_penetration
  是被动惩罚项——策略穿进楼梯才能感知台阶存在，没有任何前向感知。

  这意味着当前方案本质上是在训练盲目鲁棒步态，而非感知引导的运动规划。两者
  sim-to-real 风险有量级差异：
  - 盲目步态：落脚位置误差积累，真实机器人最终摔倒
  - 感知步态：可在落脚前预判台阶高度，动态调整

  建议 Phase 2 引入局部 heightmap 作为策略观测（参考 Perceptive Parkour
  设计），为 Phase 3 真机部署打基础。

  ---
  关键背景（从代码确认的事实）

  V11 当前已经是纯下肢版本（12-DOF，upper body 
  fixed，第7行注释明确写了）。而你现在问的 29-DOF 版是 beyondmimic_action_scale
  + 全身执行器的配置。

  所以问题核心是：如何在保持 AMP 
  全身分布完整性的前提下，让策略优先学好下肢楼梯步态。

  ---
  三个方向，各有侧重

  ---
  方向 A：梯度路由（Gradient Routing）

  核心思想：不改动 AMP 输入，而是在策略网络内部做上下肢解耦。

  具体实现：
  - Stop-gradient on upper body 
  branch：策略网络分叉为上肢子网和下肢子网，任务奖励的梯度只回传到下肢子网，AMP
  reward 的梯度两路都回传
  - 上肢子网的输出 target 是 MoCap 的参考上肢位置（监督信号），不参与任务探索
  - 下肢子网全力学习楼梯步态

  优点：AMP discriminator 看到的是完整全身状态，统计基础不变；上肢是"跟随"而非"
  固定"，自然保持角动量配合。
  缺点：需要改 ppo.py 或 runner，工程量中等；上下肢子网的 split 方式需要设计。

  ---
  方向 B：分层 AMP 权重调度（Staged Style Weight）

  核心思想：不改网络结构，改训练节奏。

  Phase 1: w_style = 0   →  纯任务奖励，下肢自由探索楼梯步态
  Phase 2: w_style = 0.1 →  轻度风格约束，修剪奇怪步态
  Phase 3: w_style = 0.3 →  正常 AMP 强度，全身风格收敛

  关键点：Phase 1 期间上肢用 scale=0.1 + joint_deviation_square 
  惩罚拉回默认姿态，既不完全固定（保留物理正确性），又不干扰下肢学习。

  优点：零工程量，纯配置修改；逻辑最简单，最容易 debug。
  缺点：Phase 1→2 切换时 discriminator
  是冷启动，可能有短暂不稳定期（但影响有限）。

  ---
  方向 C：AMP 分项 Discriminator（Upper/Lower 解耦判别器）

  核心思想：保留两个 discriminator，下肢 disc 权重高，上肢 disc
  权重低，各自独立训练。

  r_style = w_lower * disc_lower(lower_state) + w_upper *
  disc_upper(upper_state)
  w_lower = 0.6, w_upper = 0.1（楼梯阶段）

  优点：上下肢风格约束强度可以独立调节，是目前最灵活的方案；楼梯通过后可以把
  w_upper 慢慢提高到 0.5，平滑回归全身风格。
  缺点：需要改 WASABI/AMP 的 discriminator 实现，工程量最高；双 disc
  会增加显存和训练时间约 10-15%。

  ---
  关于 volume_points_penetration vs dont_wait 的额外想法

  还有一个独立思路：把被动碰撞惩罚改为主动预测惩罚。

  当前 volume_points_penetration
  是：脚已经穿进障碍物了才惩罚（速度×穿透深度），策略只能被动响应。

  更好的设计：在脚 swing
  轨迹前方做预测性惩罚——如果预计下一步落脚点有台阶碰撞，提前给一个较小的惩罚；实
  际穿透时才给大惩罚。这样梯度信号更早，策略有更长的时间窗口来调整步态。

  （不过这需要添加新的 reward 函数，复杂度比奖励权重调整高一档。）

  ---
  我的推荐

  Phase 1：方向 B（零工程量，先跑起来）
  - w_style = 0，上肢 scale=0.1 + joint_deviation_square 约束
  - 专注解决"驻停"问题，让策略先出现楼梯轨迹

  Phase 2+：方向 A（梯度路由，长期最优）
  - 上下肢梯度解耦，AMP discriminator 保持全身
  - 可复用现有的 PPO runner 结构，只需在 network forward 时加 stop-grad

  ---
